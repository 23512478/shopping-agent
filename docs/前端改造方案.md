# 前端改造方案：从「Agent 调试台」到「消费级导购 App」

> 讨论日期：2026-10-13
> 目标：把当前只有一个对话页 + 失败任务页的前端，改造成多页面、卡片化、可下单跳转的消费级购物导购应用。

## 〇、决策基线（已拍板）

1. **下单链路 = 跳转第三方平台**（京东联盟 CPS 导购模式）。站内不收款，只记录一笔「意向单」，点击跳到对应平台。
2. **商品卡片 / 详情数据 = 补齐后端字段**。给商品补 `image / description / urls`，前端拿真数据渲染，不用生成图硬顶。

理由：商品与价格都来自第三方平台，我们没有支付资质；导购模式下"跳转 + 意向单"是真实、可落地的形态。

---

## 一、现状问题（实测 + 代码确认）

| # | 问题 | 证据 |
|---|---|---|
| 1 | 全站只有 2 个视图，无路由、无导航 | `frontend/src/App.tsx`：左侧「对话 / 失败任务」两个 Tab |
| 2 | 失败任务（死信队列）直接暴露给 C 端 | `DeadLetterPage.tsx`：节点 ID、最后错误栈、建议修复、输入快照 |
| 3 | 搜货结果是纯文字，不是商品卡片 | `AgentTrace.tsx` 的 `assistantText()` 把 state JSON 翻成文字，无图、无平台标签、不可点 |
| 4 | 没有个人主页 | 后端已有画像 / 情景记忆 / 盯价数据，前端一个入口都没有 |
| 5 | 下单只是个审批弹窗，没有订单页 | `ApprovalModal.tsx` 通过 / 驳回，通过后无任何"买到"呈现 |
| 6 | 视觉像购物 App，交互像调试工具 | `index.css` 紫蓝粉渐变设计系统 vs 调试详情 / 死信字段 |

根因：前端是"给评委看 Agent 推理"的，不是"给用户买东西"的。

## 二、信息架构与路由

引入 `react-router-dom`，`App.tsx` 改为「全局导航 + 路由」结构。

| 路由 | 页面 | 作用 |
|---|---|---|
| `/` | 首页 | 搜索框、分类入口、AI 导购入口、最近浏览 |
| `/search?q=&budget=` | 搜索结果 | 商品卡片网格 |
| `/product/:id` | 商品详情 | 大图 + 多平台比价 + 店铺分 / 差评率 + 「去 XX 购买」跳转 |
| `/chat` | AI 导购 | 保留现有 Agent 能力，结果渲染成商品卡片 |
| `/orders`、`/orders/:id` | 我的订单 | 意向单列表 / 详情（含跳转链接） |
| `/me` | 个人主页 | 画像偏好、我的订单、我的盯价、历史对话 |
| `/admin/deadletter` | 失败任务 | 运维排查，**不进任何 C 端导航** |

导航：桌面顶部导航（首页 · AI 导购 · 订单 · 我的）；移动端底部 Tab 栏。

## 三、前端改造清单

- `main.tsx` 挂 `BrowserRouter`；`App.tsx` 改为 `Layout + <Routes>`
- 新增 `pages/`：`Home.tsx`、`Search.tsx`、`ProductDetail.tsx`、`Chat.tsx`（由现有 `AgentTrace.tsx` 抽取）、`Orders.tsx`、`Me.tsx`
- 新增 `components/`：`ProductCard.tsx`、`PlatformPriceList.tsx`、`NavBar.tsx`
- **搜货 / 比价结果卡片化**：`AgentTrace.tsx` 的 `assistantText()` 改为渲染 `ProductCard` 列表，点卡片 → `/product/:id`；原始节点 JSON 轨迹保留但默认收起（"看 AI 推理过程"用）
- `ApprovalModal.tsx` 语义从「审批」改成「确认下单」，通过后跳 `/orders`
- `DeadLetterPage.tsx` 挪到 `/admin/deadletter`，C 端错误只显示人话（"暂时没查到，稍后再试"）
- `index.css` 补卡片 / 详情 / 列表 / 导航样式

## 四、后端改造清单

前端只连 backend，不直连 MCP，所以需要一个中转层。

### 4.1 MCP 契约扩展（新增 1 个工具，现有三契约不动）

```
POST /tools/product_detail
  {product_ids: [...]}
-> {products: [{product_id, name, category, brand, tags,
                description, image,
                platforms: {平台: {price, url}}}]}
```

现有 `product_search` / `price_query` / `review_risk` 契约保持不变，避免动上游节点。

### 4.2 Backend 新增 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/products?ids=` | 批量卡片数据 |
| GET | `/api/products/{id}` | 商品详情 |
| GET | `/api/search?q=&budget=` | 首页 / 搜索页，内部串 product_search + product_detail |
| POST / GET | `/api/orders` | 创建 / 列出意向单 |
| GET | `/api/orders/{id}` | 意向单详情 |
| GET | `/api/profile` | 个人主页聚合（画像偏好 + 最近摘要 + 订单数 + 盯价） |
| GET | `/api/monitor` | 盯价订阅列表 |

### 4.3 数据层

- mock `mcp_server/data/products.json` 每条补 `image`（text_to_image 生成图）、`description`、`urls`（各平台链接）。
  **`platforms` 结构保持 `{平台: 价格}` 不动**，另加 `urls`，避免动 `_min_price` / `price_query`。
- 京东真实池 `sources/jd_pool.py` 的 `normalize()` 补图片 / 推广链接映射（字段名需实测）。
- 新增 `orders` 表（PostgreSQL）+ alembic 迁移。

## 五、外部 API 需求（跳转链接 & 详情卡片）

**结论：详情卡片零新增外部 API；跳转只有"精确跳京东商品页"用到联盟 API（已有），其余都是 URL 拼接。**

### 5.1 商品详情卡片

| 数据 | 来源 | 是否需要新外部 API |
|---|---|---|
| 图 / 描述 / 链接（mock 商品） | 我们手写进 products.json；图用 text_to_image 生成 | 否 |
| 图 / 链接（京东真实商品） | 京东联盟 API 返回，`normalize()` 保留即可 | 否（同一凭证） |
| 价格 / 店铺分 / 差评率 | 已有 `price_query` / `review_risk` | 否 |

### 5.2 跳转链接

| 跳法 | 需要的外部 API | 现状 |
|---|---|---|
| 跳到**该商品的搜索列表页**（`search.jd.com/Search?keyword=...`） | 不需要，纯 URL 模板拼接 | 现在就能做 |
| 跳到**某平台的具体商品详情页** | 需要该平台联盟 / 开放 API 提供落地页链接 | 京东：联盟 API 的 `materialUrl`（已有凭证，需实测字段名）；天猫：淘宝客；拼多多：多多进宝 |

### 5.3 本项目落地方式

- **京东商品**：优先用联盟 API 返回的真实落地页链接，精确跳转；拿不到就退化成搜索页链接。
- **天猫 / 拼多多（mock 数据）**：统一用搜索页 URL 模板拼接（`s.taobao.com/search?q=` / `mobile.yangkeduo.com/search_result.html?search_key=`），零 API。

## 六、风险点

1. **商品链接字段名未确认**：京粉返回里是否带 `materialUrl` / `imageUrl` 需实测；拿不到则京东也只能跳搜索页。
2. **mock 商品图**：12 条 mock 是真实型号却没有图，用 text_to_image 生成，需与"图是真实的"预期对齐。
3. **SPA 路由兜底**：生产是 nginx 静态托管，加前端路由要补 `try_files ... /index.html`。
4. **资质约束**：只有京东有真实数据和凭证，天猫 / 拼多多是 mock。演示可接受；做成商业产品才需要淘客 / 多多进宝资质。

---

## 七、落地顺序与验收

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **P0** | 路由 + 导航 + 拆页 + 失败任务移出 C 端 | 首页 / 搜索 / 详情 / 我的 都能点进去，C 端看不到"失败任务" |
| **P1** | MCP `product_detail` + `/api/search` + mock 补字段 | 搜"降噪耳机"→ 出商品卡片网格 → 点进详情看各平台价格 → 点「去京东购买」跳转 |
| **P2** | 意向单表 + orders API + 审批弹窗改造 | 对话里确认下单 → "我的订单"看到一笔 → 点击跳平台 |
| **P3** | `/api/profile` + `/api/monitor` + 个人主页 | 个人主页显示画像偏好、订单、盯价 |

---

## 八、可行性结论

项目**可行性不欠缺**，缺的是最外层展示壳，不是骨架。

已跑通、无可行性问题的部分：LangGraph 编排、Supervisor 意图解析（真模型 10/10）、三层记忆、韧性（重试 / 熔断 / 死信）、MCP 工具层、京东联盟真实数据接入；真模型 200 条评测路由 94.5%、召回 99.5%，三档故障恢复率 99% / 100% / 98%，全超 90% 验收线。

真正的缺口仅两块，且都是"贴皮"工程：

1. 前端展示层——调试台形态 → 多页面 + 商品卡片；
2. 商品数据完整度——补图片 / 描述 / 链接字段。

一句话：**引擎和骨架都通了，差的是给用户看的那层壳。**
